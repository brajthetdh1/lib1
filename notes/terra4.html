Introduction to Terraform Modules

What You'll Learn

This comprehensive guide covers everything from basic module concepts to advanced patterns used in production environments.

Terraform modules are containers for multiple resources that are used together. A module consists of a collection of .tf files kept together in a directory.

Benefits of Modules

  • Reusability across projects
  • Consistency and standardization
  • Abstraction of complexity
  • Team collaboration

Module Types

  • Root Module
  • Child Modules
  • Published Modules

What are Terraform Modules?

Module Definition

A Terraform module is a set of Terraform configuration files in a single directory. Even a simple configuration consisting of a single directory with one or more .tf files is a module.

Root Module

The main directory where you run terraform commands

Child Module

Reusable module called from root or other modules

Published Module

Modules from Terraform Registry or other sources

Key Insight

Every Terraform configuration has at least one module, known as the root module. Additional modules can be called from the root module or from other modules.

Module Structure & Organization

Standard Module Structure

modules/
├── network/
│   ├── main.tf
│   ├── variables.tf
│   ├── outputs.tf
│   └── README.md
├── compute/
│   ├── main.tf
│   ├── variables.tf
│   ├── outputs.tf
│   └── README.md
└── database/
    ├── main.tf
    ├── variables.tf
    ├── outputs.tf
    └── README.md

Required Files

  • main.tf - Main resource definitions
  • variables.tf - Input variable definitions
  • outputs.tf - Output value definitions

Optional Files

  • versions.tf - Terraform version constraints
  • README.md - Documentation
  • providers.tf - Provider configurations

Creating Your First Module

Step-by-Step Guide

Follow these steps to create a reusable VPC module

1

Create Module Directory Structure

mkdir -p modules/vpc
cd modules/vpc
touch main.tf variables.tf outputs.tf
2

Define Variables (variables.tf)

variable "vpc_name" {
  description = "Name of the VPC"
  type        = string
}

variable "vpc_cidr" {
  description = "CIDR block for the VPC"
  type        = string
  default     = "10.0.0.0/16"
}

variable "availability_zones" {
  description = "List of availability zones"
  type        = list(string)
  default     = ["us-west-2a", "us-west-2b"]
}
3

Create Resources (main.tf)

resource "aws_vpc" "main" {
  cidr_block           = var.vpc_cidr
  enable_dns_hostnames = true
  
  tags = {
    Name = var.vpc_name
  }
}

resource "aws_subnet" "private" {
  count             = length(var.availability_zones)
  vpc_id            = aws_vpc.main.id
  cidr_block        = cidrsubnet(var.vpc_cidr, 8, count.index)
  availability_zone = var.availability_zones[count.index]
  
  tags = {
    Name = "${var.vpc_name}-private-${count.index}"
  }
}
4

Define Outputs (outputs.tf)

output "vpc_id" {
  description = "ID of the VPC"
  value       = aws_vpc.main.id
}

output "private_subnet_ids" {
  description = "IDs of private subnets"
  value       = aws_subnet.private[*].id
}

output "vpc_cidr_block" {
  description = "CIDR block of the VPC"
  value       = aws_vpc.main.cidr_block
}

Using Modules in Your Configuration

Module Sources

Terraform modules can be sourced from local directories, GitHub, Terraform Registry, or other Git repositories.

Local Modules 

module "vpc" {
  source = "./modules/vpc"
  
  vpc_name          = "production-vpc"
  vpc_cidr          = "10.1.0.0/16"
  availability_zones = ["us-west-2a", "us-west-2b", "us-west-2c"]
}

GitHub Modules 

module "vpc" {
  source = "github.com/terraform-aws-modules/terraform-aws-vpc"
  
  name = "production-vpc"
  cidr = "10.1.0.0/16"
  
  azs             = ["us-west-2a", "us-west-2b"]
  private_subnets = ["10.1.1.0/24", "10.1.2.0/24"]
  public_subnets  = ["10.1.101.0/24", "10.1.102.0/24"]
}

Terraform Registry Modules 

module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 3.0"
  
  name = "production-vpc"
  cidr = "10.1.0.0/16"
  
  azs             = ["us-west-2a", "us-west-2b", "us-west-2c"]
  private_subnets = ["10.1.1.0/24", "10.1.2.0/24", "10.1.3.0/24"]
  public_subnets  = ["10.1.101.0/24", "10.1.102.0/24", "10.1.103.0/24"]
  
  enable_nat_gateway = true
  enable_vpn_gateway = true
}

Important Note

After adding or modifying modules, always run terraform init to download and initialize the modules.

Module Best Practices

Do's

  • Use semantic versioning for modules
  • Provide comprehensive documentation
  • Include examples in the repository
  • Use variables for customization

Don'ts

  • Hardcode values in modules
  • Create overly complex modules
  • Mix multiple concerns in one module
  • Forget to test modules thoroughly

Advanced Module Patterns

Conditional Resources

Create resources conditionally based on input variables.

resource "aws_nat_gateway" "this" {
  count = var.create_nat_gateway ? 1 : 0
  
  allocation_id = aws_eip.nat[0].id
  subnet_id     = aws_subnet.public[0].id
  
  tags = {
    Name = "${var.vpc_name}-nat"
  }
}

Dynamic Blocks

Generate multiple similar configuration blocks dynamically.

resource "aws_security_group" "web" {
  name_prefix = "web-"
  vpc_id      = aws_vpc.main.id

  dynamic "ingress" {
    for_each = var.web_ports
    content {
      from_port   = ingress.value
      to_port     = ingress.value
      protocol    = "tcp"
      cidr_blocks = ["0.0.0.0/0"]
    }
  }
}

Module Composition

Combine multiple modules to create complex infrastructure.

module "vpc" {
  source = "./modules/vpc"
  
  vpc_name = "app-vpc"
  vpc_cidr = "10.0.0.0/16"
}

module "eks" {
  source = "./modules/eks"
  
  cluster_name = "app-cluster"
  vpc_id       = module.vpc.vpc_id
  subnet_ids   = module.vpc.private_subnet_ids
}

module "rds" {
  source = "./modules/rds"
  
  database_name = "appdb"
  vpc_id        = module.vpc.vpc_id
  subnet_ids    = module.vpc.private_subnet_ids
}
