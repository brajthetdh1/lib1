What is Terraform State?

Core Concept

Terraform must store state about your managed infrastructure and configuration. This state is used by Terraform to map real world resources to your configuration.

Resource Mapping

Maps configuration resources to real infrastructure objects in cloud providers

Metadata Storage

Stores resource dependencies and attributes for dependency resolution

State File Structure (JSON)

{
  "version": 4,
  "terraform_version": "1.5.0",
  "serial": 1,
  "lineage": "a1b2c3d4-5678-90ef-ghij-klmnopqrstuv",
  "outputs": {},
  "resources": [
    {
      "mode": "managed",
      "type": "aws_instance",
      "name": "web",
      "provider": "provider[\"registry.terraform.io/hashicorp/aws\"]",
      "instances": [
        {
          "schema_version": 1,
          "attributes": {
            "ami": "ami-0c55b159cbfafe1d0",
            "instance_type": "t2.micro",
            "id": "i-1234567890abcdef0"
          }
        }
      ]
    }
  ]
}

Why State is Essential

Track Resource State

Knows current vs desired state for planning changes

Dependency Mapping

Understands resource relationships and creation order

Performance

Caches resource data for faster operations

Critical Warning

Never manually edit the state file. Always use Terraform commands for state modifications.

State Files & Formats

terraform.tfstate

Primary state file containing current infrastructure state in JSON format.

  • • Contains resource mappings and metadata
  • • JSON format for readability
  • • Should be stored securely

terraform.tfstate.backup

Backup of previous state file before the last operation.

  • • Automatic backup created on state modifications
  • • Useful for recovery scenarios
  • • Same format as main state file

Local State Limitations

  • • Not suitable for team collaboration
  • • Risk of state file loss or corruption
  • • No locking mechanism
  • • Difficult to version control securely

State Backends

What are Backends?

Backends define where Terraform's state is stored and how operations are executed.

Local Backend

terraform {
  backend "local" {
    path = "terraform.tfstate"
  }
}

Default backend storing state locally on disk.

S3 Backend

terraform {
  backend "s3" {
    bucket = "my-terraform-state"
    key    = "path/to/state.tfstate"
    region = "us-east-1"
  }
}

Remote backend using AWS S3 for state storage.

State Locking

Prevent Concurrent Modifications

State locking prevents multiple users from running Terraform simultaneously on the same state, preventing conflicts and corruption.

S3 Backend with DynamoDB Locking

terraform {
  backend "s3" {
    bucket         = "my-terraform-state-bucket"
    key            = "global/s3/terraform.tfstate"
    region         = "us-east-1"
    dynamodb_table = "terraform-state-locks"
    encrypt        = true
  }
}

With Locking

  • Prevents state corruption
  • Safe team collaboration
  • Shows clear error messages

Without Locking

  • Risk of state corruption
  • Unsafe for teams
  • Silent data loss possible

Remote State & Data Sharing

Share State Between Configurations

Remote state allows different Terraform configurations to share information through state data sources.

Network Configuration

# network/terraform.tf
terraform {
  backend "s3" {
    bucket = "my-company-terraform"
    key    = "network/terraform.tfstate"
    region = "us-east-1"
  }
}

output "vpc_id" {
  value = aws_vpc.main.id
}

output "private_subnet_ids" {
  value = aws_subnet.private[*].id
}

Application Configuration

# app/terraform.tf
data "terraform_remote_state" "network" {
  backend = "s3"
  config = {
    bucket = "my-company-terraform"
    key    = "network/terraform.tfstate"
    region = "us-east-1"
  }
}

resource "aws_instance" "app" {
  ami           = "ami-0c55b159cbfafe1d0"
  instance_type = "t2.micro"
  subnet_id     = data.terraform_remote_state.network.outputs.private_subnet_ids[0]
  
  tags = {
    Name = "app-server"
  }
}

Best Practice

Use remote state data sources instead of hardcoding values between environments. This creates explicit dependencies and ensures consistency.

State Operations & Commands

terraform state list

List all resources in the state file.

$ terraform state list
aws_instance.web
aws_vpc.main
aws_subnet.private[0]
aws_subnet.private[1]

terraform state show

Show attributes of a specific resource.

$ terraform state show aws_instance.web

# aws_instance.web:
resource "aws_instance" "web" {
    ami                          = "ami-0c55b159cbfafe1d0"
    instance_type               = "t2.micro"
    availability_zone           = "us-west-2a"
    # ... more attributes
}

terraform state mv

Move resources within the state file.

$ terraform state mv \
  aws_instance.old_name \
  aws_instance.new_name

terraform state rm

Remove resources from state (does not destroy infrastructure).

$ terraform state rm aws_instance.old_instance

terraform import

Import existing infrastructure into Terraform state.

$ terraform import aws_instance.web i-1234567890abcdef0

State Management Best Practices

✅ Do These

  • Use remote backends for teams
  • Enable state locking always
  • Encrypt state files at rest
  • Use least privilege access
  • Version state bucket with object versioning

❌ Avoid These

  • Never commit state files to version control
  • Don't manually edit state files
  • Avoid local state in production
  • Don't share state backend credentials
  • Never disable state locking

Secure S3 Backend Configuration

# backend.hcl
bucket         = "company-terraform-state-prod"
key            = "environments/prod/terraform.tfstate"
region         = "us-east-1"
dynamodb_table = "terraform-state-locks-prod"
encrypt        = true

# Optional: Use KMS for encryption
kms_key_id     = "alias/terraform-state-key"

# Optional: Use IAM Role instead of credentials
role_arn       = "arn:aws:iam::123456789012:role/TerraformBackend"
