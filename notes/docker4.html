Docker Daemon – The Engine Room

The persistent background process dockerd

The Docker Daemon (dockerd) is the persistent background service that manages containers, images, networks, and volumes. It listens for API requests and orchestrates the entire container lifecycle.

Container Management

Creates, starts, stops, and removes containers. Handles the container lifecycle from creation to deletion.

📦 Core responsibility

Image Management

Pulls, builds, and stores images locally. Manages layers and maintains the image cache.

🖼️ Layer storage

Network & Volume

Configures network bridges, iptables rules, and manages volumes & volume drivers.

🔌 Plugin support
Client dockerd containerd runc Kernel
Listens on Unix socket /var/run/docker.sock (or TCP) Requires root privileges (or rootless mode)

Daemon Architecture – Internal Components

Modular subsystems

API Server

Exposes the REST API (/v1.41/). Handles authentication, request routing, and version negotiation.

Image Store

Manages image layers using storage drivers (overlay2, aufs, etc.). Handles pull, push, and cache.

Network Controller

Configures network namespaces, bridges, iptables, and supports CNI/CNM plugins.

Volume Manager

Manages volumes and volume drivers. Handles mount/unmount operations and lifecycle.

Modern architecture: dockerd delegates container execution to containerd via gRPC, making it more modular and resilient.

Daemon Configuration – daemon.json

Customize daemon behavior

The daemon is configured via /etc/docker/daemon.json. Here are common settings:

{   "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  },
  "storage-driver": "overlay2",
  "data-root": "/var/lib/docker",
  "live-restore": true,
  "userns-remap": "default",
  "registry-mirrors": ["https://mirror.gcr.io"]
}

Logging

Set log driver, rotation, and limits.

Registry

Live Restore – Daemon Resilience

Keep containers running during daemon restart

Live Restore allows the daemon to restart without stopping containers. The containerd-shim keeps containers running.

# Enable live-restore in daemon.json
{
  "live-restore": true
}

Benefits

✅ Zero downtime for running containers

✅ Daemon upgrades without disruption

✅ Recovery from daemon crashes

Caveats

⚠️ Docker commands won't work during restart

⚠️ Network changes may not apply until restart

How it works: containerd-shim remains as the parent of container processes. When dockerd restarts, it reconnects to the shim and resumes management.

Securing the Daemon

Best practices for production

Rootless Mode

Run the daemon and containers without root privileges. Uses user namespaces and slirp4netns.

$ dockerd-rootless-setuptool.sh install

TLS Authentication

Secure remote daemon access with TLS client certificates. Prevents unauthorized API access.

# Start with TLS
dockerd --tlsverify --tlscacert=ca.pem \   --tlscert=cert.pem --tlskey=key.pem

Security Options

  • Seccomp: Restrict syscalls (--seccomp-profile)
  • AppArmor/SELinux: MAC profiles
  • User namespace remapping: --userns-remap
  • Capabilities: Drop unnecessary capabilities

Daemon Plugins – Extending Functionality

Network, volume, authorization, logging

Network Plugins

Add support for overlay networks, SDN, and custom networking stacks.

🌐 Calico, Weave, Flannel

Volume Plugins

Extend storage to NFS, cloud storage (EBS, Azure File), and distributed FS.

💾 Portworx, REX-Ray

Logging Plugins

Forward logs to external systems (Fluentd, Splunk, AWS CloudWatch).

📊 Fluentd, Logstash
# Install a plugin
$ docker plugin install vieux/sshfs --alias sshfs

# Use the plugin
$ docker volume create --driver sshfs \   --opt sshcmd=user@host:/path \   --opt password=secret \   sshvolume
Plugins run as containers and communicate via Unix sockets
