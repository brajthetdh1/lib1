How to Run Your First Container

Hello World
# Run a simple container
$ docker run hello-world

# Run Ubuntu interactively
$ docker run -it ubuntu:22.04 /bin/bash

# Run Nginx in background
$ docker run -d --name webserver -p 8080:80 nginx
  • 1 Docker pulls the image (if not locally cached)
  • 2 Creates a container from the image
  • 3 Starts the container process
  • 4 Outputs "Hello from Docker!"
    • Success: You've run your first container!

    How to List Containers

    See what's running
    # List running containers
    $ docker ps

    # List all containers (including stopped)
    $ docker ps -a

    # List only container IDs
    $ docker ps -q

    # List with custom format
    $ docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"

    Filtering

    $ docker ps --filter "status=exited"
    $ docker ps --filter "name=web"
    $ docker ps --filter "label=environment=prod"

    Common Columns

    • CONTAINER ID – Unique ID
    • IMAGE – Image used
    • COMMAND – Running command
    • STATUS – Running/Exited/Paused

    How to Inspect a Container

    Deep dive into container details
    # Full inspection
    $ docker inspect container-name

    # Get specific fields
    $ docker inspect --format='{{.State.Status}}' container
    running

    $ docker inspect --format='{{.NetworkSettings.IPAddress}}' container
    172.17.0.2

    $ docker inspect --format='{{.Config.Image}}' container

    State

    Status, PID, exit code, start time

    Network

    IP, ports, network settings

    Mounts

    Volumes and bind mounts

    Tip: Use jq for parsing JSON output: docker inspect container | jq .[0].State

    How to Execute Commands in Containers

    Inside the container
    # Open interactive shell
    $ docker exec -it container bash

    # Run a single command
    $ docker exec container ls -la /app

    # Run in a specific working directory
    $ docker exec -w /app container node app.js

    # Set environment variable
    $ docker exec -e MY_VAR=value container printenv
    Note: docker exec runs new processes inside an already running container. It's different from docker attach (which attaches to the main process).

    How to View Container Logs

    Debugging and monitoring
    # View logs
    $ docker logs container

    # Follow logs (like tail -f)
    $ docker logs -f container

    # Show last N lines
    $ docker logs --tail 100 container

    # Show logs since timestamp
    $ docker logs --since 2024-01-01T00:00:00 container

    Log Rotation

    $ docker run --log-opt max-size=10m \
      --log-opt max-file=3 nginx

    Log Drivers

    • json-file (default)
    • syslog, fluentd
    • awslogs, splunk

    How to Stop, Start, Restart Containers

    Container lifecycle management
    # Stop a running container
    $ docker stop container

    # Stop with custom timeout (30 seconds)
    $ docker stop -t 30 container

    # Start a stopped container
    $ docker start container

    # Restart a container
    $ docker restart container

    Graceful Shutdown

    Docker sends SIGTERM to allow cleanup, then SIGKILL after timeout.

    Force Kill

    $ docker kill container
    $ docker kill --signal=SIGQUIT container

    How to Remove Containers

    Clean up unused containers
    # Remove a stopped container
    $ docker rm container

    # Remove a running container (force)
    $ docker rm -f container

    # Remove multiple containers
    $ docker rm container1 container2 container3

    # Remove all stopped containers
    $ docker container prune

    # Remove all containers
    $ docker rm -f $(docker ps -aq)
    Warning: Removing a container deletes its writable layer. Use volumes for persistent data.

    How to Pull Images from Registry

    Download images
    # Pull latest tag
    $ docker pull nginx

    # Pull specific version
    $ docker pull ubuntu:22.04

    # Pull from private registry
    $ docker pull myregistry.com/myapp:v1

    # Pull by digest (immutable)
    $ docker pull nginx@sha256:abc123...

    Registry Mirrors

    # daemon.json
    { "registry-mirrors": ["https://mirror.gcr.io"] }

    Login to Registry

    $ docker login docker.io
    $ docker login myregistry.com

    How to Push Images to Registry

    Share your images
    # Tag image for registry
    $ docker tag myapp:latest docker.io/myuser/myapp:v1

    # Push the image
    $ docker push docker.io/myuser/myapp:v1

    # Push to private registry
    $ docker tag myapp private-registry:5000/myapp:v1
    $ docker push private-registry:5000/myapp:v1
    Note: You must be logged in (docker login) to push to a registry.

    How to Build a Docker Image

    From Dockerfile to image
    # Basic build
    $ docker build -t myapp:latest .

    # Build with specific Dockerfile
    $ docker build -f Dockerfile.prod -t myapp:prod .

    # Build with BuildKit (recommended)
    $ DOCKER_BUILDKIT=1 docker build -t myapp .

    # Build with build arguments
    $ docker build --build-arg VERSION=2.0 -t myapp .
  • 1 Create a Dockerfile
  • 2 Write instructions (FROM, RUN, COPY, etc.)
  • 3 Run docker build
  • 4 Image is created and stored locally

    • How to Write a Dockerfile – Example

    Node.js application
    # Dockerfile for Node.js app
    FROM node:18-alpine
    WORKDIR /app
    COPY package*.json ./
    RUN npm install
    COPY . .
    EXPOSE 3000
    CMD ["npm", "start"]

    Best Practices

    • Use Alpine for smaller size
    • Copy package files first (cache)
    • Set WORKDIR
    • Use non-root user

    Build & Run

    $ docker build -t node-app .
    $ docker run -p 3000:3000 node-app

    How to Use Multi-Stage Builds

    Smaller images
    # Build stage
    FROM golang:1.19 AS builder
    WORKDIR /app
    COPY . .
    RUN go build -o myapp .

    # Runtime stage (smaller)
    FROM alpine:latest
    COPY --from=builder /app/myapp /usr/local/bin/
    CMD ["myapp"]

    Benefits

    • ✅ Much smaller final images
    • ✅ No build tools in runtime
    • ✅ Better security

    Size Comparison

    • Full Go image: ~800MB
    • Alpine runtime: ~10MB

    How to Use Build Cache Effectively

    Faster builds
    # Efficient Dockerfile – dependencies first
    FROM node:18-alpine
    WORKDIR /app
    # COPY package files first (changes less often)
    COPY package*.json ./
    RUN npm install # Cached unless package.json changes
    # COPY source code last (changes often)
    COPY . .
    CMD ["npm", "start"]
    Golden Rule: Order layers from least to most frequently changing. This maximizes cache reuse.

    Use Cache from Previous Build

    $ docker build --cache-from myapp:latest -t myapp:new .

    Ignore Cache

    $ docker build --no-cache -t myapp .

    How to Use .dockerignore

    Exclude files from build context
    # Example .dockerignore
    node_modules/
    .git/
    .env
    *.log
    Dockerfile
    .dockerignore
    README.md
    tests/
    coverage/

    Benefits

    • ✅ Faster builds (less data to send)
    • ✅ Smaller build context
    • ✅ Prevents secrets in images

    Common Mistakes

    • ⚠️ Forgetting to ignore node_modules
    • ⚠️ Not ignoring .env

    How to Tag Images

    Version control
    # Tag an existing image
    $ docker tag nginx:latest nginx:v1.21

    # Tag for registry
    $ docker tag myapp:latest docker.io/myuser/myapp:v1.0.0

    # Tag with multiple tags
    $ docker tag myapp:latest myapp:v1
    $ docker tag myapp:latest myapp:v1.0.0
    Best Practice: Use semantic versioning (v1.2.3) for releases. Use latest sparingly in production.

    How to Save and Load Images

    Offline transfer
    # Save image to tar file
    $ docker save -o myapp.tar myapp:latest
    $ docker save myapp:latest > myapp.tar

    # Load image from tar file
    $ docker load -i myapp.tar
    $ docker load < myapp.tar

    Use Cases

    • Air-gapped environments
    • No registry available
    • Backup images

    vs docker export

    docker save preserves layers and metadata. docker export creates flattened filesystem.

    How to Create Volumes

    Persistent data
    # Create a named volume
    $ docker volume create mydata

    # List volumes
    $ docker volume ls

    # Inspect a volume
    $ docker volume inspect mydata

    Use Volume

    $ docker run -v mydata:/app/data nginx
    $ docker run --mount source=mydata,target=/app/data nginx

    Remove Volume

    $ docker volume rm mydata
    $ docker volume prune

    How to Use Bind Mounts

    Mount host directories
    # Mount current directory to /app
    $ docker run -v $(pwd):/app node npm start

    # Mount with --mount (explicit)
    $ docker run --mount type=bind,src=$(pwd),dst=/app node npm start

    # Read-only bind mount
    $ docker run -v $(pwd):/app:ro nginx
    Use Case: Bind mounts are great for development – edit code on host, see changes instantly in container.

    How to Use tmpfs Mounts

    In-memory storage
    # Mount tmpfs to /tmp
    $ docker run --tmpfs /tmp:rw,size=512m alpine

    # Using --mount syntax
    $ docker run --mount type=tmpfs,dst=/cache,tmpfs-size=256m nginx

    Use Cases

    • ✅ Temporary caches
    • ✅ Session data
    • ✅ Secrets (never hit disk)

    Limitations

    • ⚠️ Data lost on container stop
    • ⚠️ Limited by host RAM

    How to Copy Files to/from Containers

    Moving data
    # Copy from host to container
    $ docker cp /host/file.txt container:/app/file.txt
    $ docker cp /host/folder/ container:/app/

    # Copy from container to host
    $ docker cp container:/app/log.txt /host/log.txt
    $ docker cp container:/app/logs/ /host/logs/
    Note: docker cp works on both running and stopped containers. It copies from the container's filesystem.

    How to Publish Ports

    Expose container ports
    # Map container port 80 to host port 8080
    $ docker run -d -p 8080:80 nginx

    # Map to specific host IP
    $ docker run -d -p 127.0.0.1:8080:80 nginx

    # Random port mapping
    $ docker run -d -P nginx

    Multiple Ports

    $ docker run -p 8080:80 -p 8443:443 nginx

    Port Range

    $ docker run -p 8080-8085:80-85 nginx

    How to Create Custom Networks

    Container communication
    # Create a bridge network
    $ docker network create mynet

    # Create with specific subnet
    $ docker network create --subnet 10.10.0.0/16 mynet

    Run Containers on Network

    $ docker run -d --net mynet --name web nginx
    $ docker run -it --net mynet alpine ping web

    Network Commands

    $ docker network ls
    $ docker network inspect mynet
    $ docker network rm mynet

    How to Connect Containers on Same Network

    Service discovery
    # Create network
    $ docker network create app-network

    # Run containers on the network
    $ docker run -d --net app-network --name db postgres
    $ docker run -d --net app-network --name web --link db nginx

    # Containers can reach each other by name
    $ docker exec web ping db
    $ docker exec web nslookup db
    Tip: Using --link is legacy. Modern Docker uses DNS-based service discovery on user-defined networks.

    How to Set Environment Variables

    Configuration
    # Single variable
    $ docker run -e MY_VAR=value ubuntu env

    # Multiple variables
    $ docker run -e VAR1=val1 -e VAR2=val2 ubuntu

    # From env file
    $ docker run --env-file .env ubuntu

    Env File Format

    # .env file
    DB_HOST=localhost
    DB_PORT=5432
    DB_USER=admin

    Override

    $ export MY_VAR=value
    $ docker run -e MY_VAR ubuntu

    How to Set Restart Policies

    Self-healing
    # Always restart
    $ docker run --restart=always nginx

    # Unless stopped by user
    $ docker run --restart=unless-stopped nginx

    # Restart on failure (max 5 times)
    $ docker run --restart=on-failure:5 nginx

    Use Cases

    • always – Critical services
    • unless-stopped – Production services
    • on-failure – Batch jobs

    Note

    Restart policies apply to container exits, not to daemon restarts (use --live-restore for that).

    How to Set Resource Limits

    CPU & Memory
    # CPU limits
    $ docker run --cpus=1.5 nginx
    $ docker run --cpu-shares=512 nginx

    # Memory limits
    $ docker run --memory=512m nginx
    $ docker run --memory-swap=1g nginx

    Best Practice

    Always set memory and CPU limits in production to prevent noisy neighbors.

    View Limits

    $ docker stats container

    How to Run as Non-Root User

    Security best practice
    # Run with specific user
    $ docker run --user 1000:1000 ubuntu whoami

    # In Dockerfile
    FROM ubuntu:22.04
    RUN useradd -m -u 1000 appuser
    USER appuser
    CMD ["/app/myapp"]
    Why? Running as root is a security risk. If a container is compromised, the attacker gets root on the host.

    How to Drop Capabilities

    Least privilege
    # Drop all capabilities, add only needed
    $ docker run --cap-drop=ALL --cap-add=NET_BIND_SERVICE nginx

    # Drop specific capabilities
    $ docker run --cap-drop=SYS_ADMIN --cap-drop=SETUID nginx

    Recommended

    • Drop all: --cap-drop=ALL
    • Add only essential capabilities
    • Never add SYS_ADMIN

    Common Capabilities

    • NET_BIND_SERVICE – bind to <1024 ports
    • NET_ADMIN – network administration
    • SYS_TIME – set system time

    How to Add Health Checks

    Monitor container health
    # Dockerfile
    HEALTHCHECK --interval=30s --timeout=3s --retries=3 \
      CMD curl -f http://localhost/ || exit 1

    # docker run
    $ docker run --health-cmd="curl -f http://localhost/ || exit 1" nginx

    Health States

    • starting – Initial phase
    • healthy – Working
    • unhealthy – Failed health checks

    View Health

    $ docker inspect --format='{{.State.Health.Status}}' container

    How to Use Labels

    Metadata organization
    # Add labels when running
    $ docker run -d --label environment=production --label version=v1 nginx

    # Filter containers by label
    $ docker ps --filter "label=environment=production"
    $ docker ps --filter "label=version"

    # Inspect labels
    $ docker inspect --format='{{.Config.Labels}}' container
    Use Cases: Environment tagging, version tracking, team ownership, CI/CD pipeline tracking.

    Real-time resource usage
    # All running containers

    How to Pause and Unpause Containers

    Freeze processes
    # Pause a container
    $ docker pause container

    # Unpause a container
    $ docker unpause container
    Use Cases: Temporarily suspend a container to free resources, debugging without terminating processes.

    Important

    Paused containers consume memory but no CPU. docker stop will fail on paused containers.

    How to Export and Import Containers

    Filesystem snapshots
    # Export container filesystem
    $ docker export container > container.tar

    # Export and compress
    $ docker export container | gzip > container.tar.gz

    # Import as image
    $ docker import container.tar myapp:flat
    Note: docker export creates a flattened filesystem. It loses layer history and metadata. Use docker save for full image backup.

    How to Use Docker Compose – Basic

    Multi-container apps
    # docker-compose.yml
    version: '3'
    services:
      web:
        image: nginx
        ports:
          - "8080:80"
      db:
        image: postgres
        environment:
          - POSTGRES_PASSWORD=secret
    # Start services
    $ docker-compose up -d

    # Stop services
    $ docker-compose down

    How to Use Docker Compose – Advanced

    Volumes, networks, dependencies
    version: '3'
    services:

        build: .
        volumes:
          - ./app:/app
        depends_on:
          - db
        environment:
          - DB_HOST=db
      db:
        image: postgres:13
        volumes:
          - db-data:/var/lib/postgresql/data
    volumes:
      db-data:
    $ docker-compose up -d
    $ docker-compose logs -f
    $ docker-compose exec web bash

    How to Sign Images (Content Trust)

    Verify authenticity

    How to Clean Up Docker

    Free up disk space
    # Remove everything unused
    $ docker system prune -a -f

    # Remove only images
    $ docker image prune -a -f

    # Remove only containers
    $ docker container prune -f

    # Remove only volumes
    $ docker volume prune -f

    Check Disk Usage

    $ docker system df
    TYPE TOTAL ACTIVE SIZE
    Images 12 5 2.3GB
    Containers 8 3 456MB

    Safe Cleanup

    docker system prune removes stopped containers, unused networks, dangling images, and build cache.

    How to Backup and Restore Volumes

    Data protection
    # Backup volume to tar
    $ docker run --rm -v mydata:/data -v $(pwd):/backup alpine \
      tar czf /backup/mydata-backup.tar.gz -C /data .

    # Restore from tar
    $ docker run --rm -v mydata:/data -v $(pwd):/backup alpine \
      tar xzf /backup/mydata-backup.tar.gz -C /data
    Tip: Use a temporary container with the volume mounted to perform backup/restore operations.

    How to Update a Running Container

    Rolling updates
    # Manual update (stop, remove, run new)
    $ docker stop web
    $ docker rm web
    $ docker run -d --name web --restart=always myapp:v2

    Blue-Green Deployment

    • Run both versions side by side
    • Switch traffic to new version
    • Stop old version after testing

    Swarm Rolling Update

    $ docker service update --image myapp:v2 web

    How to Rollback a Container

    Revert to previous version
    # Rollback to previous tag
    $ docker stop web
    $ docker rm web
    $ docker run -d --name web --restart=always myapp:v1
    Best Practices:
    • Always tag images with semantic versions
    • Keep previous versions available
    • Test rollback procedure regularly

    How to Debug a Container

    Troubleshooting
  • 1 Check logs: docker logs -f container
  • 2 Exec into container: docker exec -it container bash
  • 3 Inspect container: docker inspect container
  • 4 Check stats: docker stats container
  • 5 Check events: docker events --filter container=container

    • Debug with Interactive

    $ docker run -it --entrypoint /bin/bash myapp

    Container Exit Codes

    • 0 – Normal exit
    • 1 – Application error
    • 137 – OOM killed
    • 143 – SIGTERM received

    How to Use Docker Swarm – Basic

    Orchestration
    # Initialize swarm
    $ docker swarm init

    # Join worker nodes
    $ docker swarm join --token SWMTKN-xxx manager-ip:2377

    # Deploy a service
    $ docker service create --name web --replicas 3 -p 8080:80 nginx

    Service Commands

    $ docker service ls
    $ docker service ps web
    $ docker service scale web=5

    Update Service

    $ docker service update --image myapp:v2 web

    How to Manage Secrets in Swarm

    Secure configuration
    # Create a secret
    $ echo "mysecurepassword" | docker secret create db_password -

    # Use secret in service
    $ docker service create --secret db_password --name web nginx

    # Secret is mounted in container
    $ docker exec web cat /run/secrets/db_password
    Security: Secrets are encrypted in transit and at rest. They're not stored in images or container filesystem.

    How to Handle Container Failures

    Common issues and solutions

    Container Exits Immediately

    • Check logs: docker logs
    • Process crashes on startup
    • Use -it to debug

    Port Already in Use

    • netstat -tulpn | grep :8080
    • Use different host port

    No Space Left

    • docker system prune -f
    • Check volumes: docker volume prune

    Permission Denied

    • Check --user
    • Check volume permissions
